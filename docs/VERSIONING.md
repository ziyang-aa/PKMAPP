## 日常使用方式

- `main` 保存已确认可用的 Android 代码。
- 每个新设计或功能使用一个 `codex/功能名` 分支。提交是这条分支上的一次存档。
- 开发完成后发起 Pull Request，集中查看这次修改。确认可用后合并进 `main`。
- 正式保留一个版本时创建标签，例如 `v2.0.0`，并在 Releases 附上对应 APK。标签指向源码存档，发布页提供下载。
- 小修复递增最后一位，例如 `v2.0.1`。增加功能使用 `v2.1.0`。整体定位或设计大改使用 `v3.0.0`。

新卡片设计分支为 `codex/expressive-study-card`，从第二版开始。第二版标签保持不变，试验效果确认后再合并与发布。

## 数据与兼容

APK 放在 Releases 附件，源码放在 Git。手机账本、头像、学习记录、开发日志和本机配置不作为版本内容上传。

Git 回退只能恢复代码。手机数据是独立的，旧版可能无法读取新版学习存档。需要回看第一版时，先导出账单备份，优先在单独设备或模拟器中体验。

当前 APK 使用调试签名，适合个人体验。后续发布需要持续使用同一签名，Android 的 `versionCode` 每次发布递增。第二版使用 `versionName=2.0.0`、`versionCode=2`。
